# 任务中心 UI 规范

状态：已确认，作为任务中心后续改造的视觉与交互基线。

## 1. 目标

- 用户在 3 秒内看清：是否有任务运行、完成率、失败/需关注数量、当前处理对象。
- 用状态图、比例条和时间线替代重复说明文字。
- 默认展示可操作信息；请求参数、进度载荷、结果载荷等技术数据按需展开。
- 扫描、AI 分析、人脸任务保持同一视觉语言与交互层级。

## 2. 信息层级

1. 页面级：任务中心标题、任务类型标签页。
2. 状态级：完成率环、排队/运行/完成/失败计数。
3. 操作级：一个主操作，其他操作使用次级按钮；危险操作独立使用危险色。
4. 运行级：实时活动时间线，优先显示文件名、状态和重试次数。
5. 历史级：最近任务状态分布、任务类型分布、可筛选任务列表。
6. 诊断级：失败明细先于技术 JSON；JSON 位于二级折叠区。

## 3. 视觉规范

- 延续现有品牌色 `primary`，不另建页面级硬编码色板。
- 页面最大宽度使用 `max-w-6xl`；内容间距采用 4/8px 节奏。
- 卡片使用 `canvas + hairline + rounded-md`，禁止额外阴影和渐变装饰。
- 数字使用 `tabular-nums`，状态必须同时提供文字或图标，不能仅依赖颜色。
- 图表只展示现有接口数据：
  - 完成率：`success / total`。
  - 最近状态分布：当前加载的 ProjectTask 列表。
  - 任务类型分布：当前加载的 ProjectTask 列表，最多展示前三类。
- 图表必须包含 `aria-label` 或可见数据标签，不增加仅悬停可见的信息。

## 4. 交互规范

- 标签页、按钮和筛选器最小高度 44px，保留清晰焦点环。
- 标签页使用 `role=tablist/tab` 和 `aria-selected`。
- 异步操作期间禁用按钮并显示当前动作状态。
- 最近任务提供：全部、运行中、需关注、已完成四种本地筛选。
- 展开任务后先显示失败明细和运行摘要；技术数据需再次展开。
- 动效只用于旋转加载图标和 150–200ms 状态过渡，并遵循 `prefers-reduced-motion`。

## 5. 响应式规范

- 375px：概览、图表、活动时间线和历史列表单列排列，不产生横向滚动。
- 768px：概览允许双列，任务操作自动换行。
- 1024px 及以上：工作区采用主内容 + 实时活动双列结构。
- 次要时间戳可在窄屏隐藏；任务名称和错误文本必须可换行或安全截断。

## 6. 文案规范

- 页面不重复解释配置归属或后台实现。
- 状态统一使用：排队中、运行中、已完成、需关注、已取消、已暂停。
- 面向用户的任务类型优先使用中文映射，未知类型使用可读化后的原始标识。
- 错误提示包含原因；能恢复时同时提供暂停、恢复、取消或重试操作。
